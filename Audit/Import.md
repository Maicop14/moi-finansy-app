# Импорт банковских документов

## Границы доверия

| Вход и место обработки | Куда идут данные | Условие |
| --- | --- | --- |
| Файл, фото или текст в ImportScreen | BankFiles.extract → BankRead / BankJSON → черновик | Локальная обработка, распознавание Vision |
| Расширение ShareController | Групповой контейнер Pending → тот же черновик | Пакет становится виден приложению после переноса из промежуточного каталога |
| Ручной разбор через API | Выбранный оригинал и шаблон → OpenAI | Отдельная кнопка с предупреждением, временный ключ, store=false |
| Подтверждение импорта | ImportLedger.plan → повторный расчёт → ModelContext.save | Операции и исходный документ сохраняются одной транзакцией |
| Кнопка открытия оригинала | SwiftData → временная копия → Quick Look | Копия нужна нативному просмотру |

Суммы интерпретируются в копейках. Код индексирует повторы по счёту, источнику, строке и банковскому идентификатору. Совпадения по дате и сумме требуют решения пользователя. Формулы Excel представлены формулой и сохранённым банковским значением. Результат распознавания может отличаться от документа, поэтому перед сохранением нужен просмотр.

## Исправления по итогам чтения кода

- Файловый импорт и Share теперь принимают обычные локальные файлы и проверяют количество реально прочитанных байтов. Для фото используется файловое представление. Один сеанс ограничен 20 файлами и суммарными 64 МБ, один оригинал — 24 МБ. Расширение записывает копии в iOS с защитой содержимого при блокировке.
- Проверка больших выписок перенесена ближе к разбору. Для Excel ограничены строки, ячейки и развёрнутый текст, для несжатых частей ZIP сверяются размеры. Внешние XML-сущности отключены. Для текстовых, PDF и JSON документов применяются пределы объёма текста и количества строк.
- У двух столбцов с разными валютами сумма платежа теперь сопоставляется с валютой платежа. Если рублёвый эквивалент не подтверждён или поле списания повреждено, сумма требует проверки.
- При открытии оригинала Quick Look получает отдельную временную копию на каждый просмотр. Приложение удаляет её при закрытии. При следующем просмотре удаляются уцелевшие более суток копии и копии, созданные предыдущими версиями.
- Встроенный API использует эфемерную сессию, без кэша, хранилища cookie и повторного запроса на адрес перенаправления. Объём ответа ограничен, строки из JSON включаются вручную после сверки. Политика хранения сервиса находится вне приложения.

## Остаточные условия

SwiftData сохраняет оригинал целиком по замыслу приложения. После удаления операции исходный StatementSource может остаться, так как один оригинал обслуживает несколько операций. Просмотр Quick Look использует системный процесс, жизненный цикл его собственных кэшей определяется ОС. Временные файлы в очереди Share сохраняются до разбора или ручной очистки. На Mac защита локального профиля и резервных копий зависит в том числе от FileVault и прав пользователя.

Сопоставление двух выписок без банковского идентификатора по счёту, дате и сумме не доказывает идентичность операций. Для повторного разбора одного документа методом JSON учитывается также порядок строк. Результат машинного распознавания и спорные совпадения нуждаются в сверке. Внешнюю отправку реальных выписок и работу с платным API-ключом в этой проверке не выполняли.

## Проверки

Модульные проверки на искусственных данных охватывают границу размера файла, чтение обычного файла, отклонение каталога и символической ссылки, независимое удаление двух одновременных предпросмотров, включение строк JSON после подтверждения и выбор валюты при импорте. Существующие тесты покрывают PNG/PDF OCR, Excel, дубликаты, копейки и сверку итогов месяца. Отдельно проверена сборка iOS с расширением Share. Это проверка кода и синтетических сценариев, а не сертификат безопасности операционной системы.
